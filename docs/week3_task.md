# 第3周：按键触发与物理反馈闭环

## 任务说明

### 本周问题
佩戴者按下按键，自己和查看信息的人分别应获得什么反馈？

### 目标
在现有工程中增加"按键发起教学求助测试消息"，实现：
1. 板端实体按键触发一次"教学求助测试消息"
2. 按键后本地立即给出反馈（LED/蜂鸣器/串口日志），明确"按键已触发/本地已确认"
3. 通过现有 VPS 上传求助事件，服务端存储
4. Web 查看者能看到求助事件、来源设备、时间、状态，并能"回应/取消"
5. 板端能接收远端回应/取消状态
6. 明确区分"本地已确认""已上传""查看者已回应""失败/超时/已取消"
7. 断开外网时，本地仍能确认按键已触发

### 硬件配置（降级方案）

| 器件 | 配置 | 说明 |
|------|------|------|
| 按键 | GPIO0 (BOOT键) | 低电平按下，内部上拉，50ms 软件消抖 |
| LED | GPIO_NUM_NC (-1) | **无物理 LED**，串口日志替代 |
| 蜂鸣器 | GPIO_NUM_NC (-1) | **无蜂鸣器**，串口日志替代 |
| 屏幕 | 不使用 | — |

> ⚠️ **硬件降级说明**：本次运行无物理 LED/蜂鸣器，本地反馈以串口日志为证据。
> 物理反馈闭环中"实体反馈输出"标记为 **待补验**，不算完成。

### 状态机

```
idle → local_ack → uploading → delivered → acknowledged
                                  ↓
                              cancelled / failed / timeout
```

| 状态 | 含义 | 串口日志证据 |
|------|------|-------------|
| idle | 无活跃事件 | `[SOS] idle` |
| local_ack | 按键已触发，本地已确认 | `[SOS] local_ack event_id=... source=button` |
| uploading | 正在上传 | `[SOS] uploading event_id=...` |
| delivered | 服务端已接收 | `[SOS] delivered event_id=... server_received=yes` |
| acknowledged | 查看者已回应 | `[SOS] acknowledged event_id=... viewer_responded=yes` |
| cancelled | 事件已取消 | `[SOS] cancelled event_id=...` |
| failed | 上传失败 | `[SOS] failed event_id=...` |
| timeout | 超时 | `[SOS] timeout event_id=...` |

### 取消规则
- `cancelled` 为终态，不可被 `acknowledged` 覆盖
- 服务端 `ack` 接口对已取消事件返回 409 Conflict
- 板端收到 `sos_cancel` 后忽略后续 `sos_response`

## 当堂验证清单

### 验证 1：断网按键本地确认
- **操作**：断开 WiFi → 按下 BOOT 键
- **预期**：串口输出 `[SOS] local_ack event_id=... source=button`
- **证据类型**：串口日志证据（无物理 LED/蜂鸣器）
- **状态**：⬜ 待验证

### 验证 2：无 server_received_at 不显示已收到
- **操作**：断网按键后查看 Web 页面
- **预期**：事件卡片显示"⚠️ 未送达/仅本地确认"，server_received_at 为空
- **证据类型**：Web 页面截图
- **状态**：⬜ 待验证

### 验证 3：正常全链路
- **操作**：联网 → 按键 → Web 显示"已送达" → 点击"回应" → 串口输出 acknowledged
- **预期**：完整状态流转，所有时间戳有值
- **证据类型**：串口日志 + API 响应 + Web 截图
- **状态**：⬜ 待验证

### 验证 4：取消后迟到 ack 返回 409
- **操作**：按键 → 取消 → 再点击"回应"
- **预期**：服务端返回 409 Conflict，板端不重新触发反馈
- **证据类型**：curl 响应 + 串口日志
- **状态**：⬜ 待验证

### 验证 5：共享设备独立 event_id
- **操作**：连续按两次按键（第一次完成后再按）
- **预期**：两个事件有不同 event_id，互不干扰
- **证据类型**：数据库查询
- **状态**：⬜ 待验证

### 验证 6：模拟事件标识
- **操作**：在 Web 页面点击"创建模拟事件"
- **预期**：事件卡片显示"⚠️ 模拟 TEST"徽章，source="test"
- **证据类型**：Web 页面截图
- **状态**：⬜ 待验证

### 验证 7：超时测试
- **操作**：创建事件后不上传（断网），等待 120 秒
- **预期**：状态变为 timeout
- **证据类型**：数据库查询
- **状态**：⬜ 待验证

### 验证 8：恢复网络补传
- **操作**：断网按键 → 恢复 WiFi → 观察串口
- **预期**：事件自动上传，状态变为 delivered
- **证据类型**：串口日志
- **状态**：⬜ 待验证
